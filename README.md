# twitter_generating_soft
=======
# Twitter Content Studio (упрощённая версия)

Инструмент теперь делает две вещи:

- анализирует готовые посты, чтобы понять стиль, тон и подсказки для промптов;
- генерирует новые посты ≤280 символов с учётом выбранного стиля/тона.

Постинг в Twitter, треды и любые приватные данные удалены.

---

## 📦 Установка

```bash
pip install -r requirements.txt
```

---

## 🔐 Настройка OpenAI ключа

1. Получите новый ключ: https://platform.openai.com/api-keys  
2. В корне проекта создайте `.env` и вставьте туда строку

```bash
   OPENAI_API_KEY=sk-...
   ```

   Альтернативно впишите ключ напрямую в `settings.py` (переменная `OPENAI_API_KEY`).

3. Отредактируйте `settings.py`:
   - `TARGET_HANDLE` — упоминание проекта в постах (например `@yourproject`);
   - `POSTS_COUNT` — количество постов по умолчанию при генерации;
   - `PROJECT_DESCRIPTION_PATH` — путь к тексту с описанием проекта (используется как контекст, файл уже очищен и содержит шаблон);
   - при необходимости скорректируйте температуры и лимиты токенов.

Все параметры также можно переопределить переменными окружения (см. подписи в `settings.py`).

## 🧭 Структура полезных файлов

```
main.py                  # консольное меню
analyze_posts.py         # отдельный скрипт анализа
generate_posts.py        # генератор постов
analysis_input.txt       # сюда вставляем тексты для анализа (по одному блоку через пустую строку)
prompt.txt               # шаблон промпта с профилями
content_utils.py         # общие функции проверки/диверсификации
twitter_tool/
  ├── config.py          # загрузка настроек и .env
  └── project_description.txt  # шаблон описания проекта (замените на свой текст)
unique/
  ├── style.txt          # стили текстов
  ├── tone.txt           # тоны (без приватных упоминаний)
  └── punctuation.txt    # профили пунктуации
```

---

## ▶️ Запуск через меню

```bash
python main.py
```

В меню две функции:

1. **Analyze posts** – считывает файл `analysis_input.txt` (можно указать свой путь), отправляет каждый пост в OpenAI и сохраняет Markdown-отчёт в `outputs/analysis_report_*.md`.
2. **Generate posts** – запускает `generate_posts.py`, использует `prompt.txt`, профили из `unique/` и сохраняет CSV в `outputs/generated_posts_*.csv`. По запросу можно указать другое количество постов.

---

## ⚙️ Прямой запуск команд

Анализ:
```bash
python analyze_posts.py --input my_posts.txt --output outputs/report.md
```

Генерация:
```bash
python generate_posts.py --count 8 --prompt-file custom_prompt.txt
```

Любой параметр можно не указывать — тогда берутся значения из `settings.py`.

---

## 📝 Что даёт каждый модуль

| Функция | Что делает | Вывод |
|---------|------------|-------|
| `analyze_posts.py` | определяет стиль, тон, краткий смысл и подсказку для промпта по каждому посту | Markdown в `outputs/analysis_report_*.md` |
| `generate_posts.py` | генерирует новые посты с учётом профилей и описания проекта | CSV с колонкой `post` |

Обе функции используют `content_utils.py` для валидации (длина ≤280, одно упоминание `TARGET_HANDLE`, фильтр служебных ответов и похожих текстов).

---

## 📚 Работа с контентом

- `prompt.txt` использует плейсхолдеры `{STYLE_PROFILE}`, `{TONE_PROFILE}`, `{PUNCTUATION_PROFILE}` и `{TARGET_HANDLE}`.  
  Измените инструкцию под свой проект, но оставьте плейсхолдеры, чтобы профили подставлялись автоматически.

- `analysis_input.txt` — просто текстовый файл. Каждый пост отделяется пустой строкой.

- `twitter_tool/project_description.txt` — шаблон, куда вы вставляете краткое описание проекта. Этот текст (если он есть) автоматически подмешивается в промпт при генерации.

---

## 🧪 Советы по использованию

- Перед генерацией обновите `unique/style.txt`, `unique/tone.txt` и `unique/punctuation.txt`, чтобы стили отражали нужную манеру речи.
- Если нужно временно отключить требование упоминания `TARGET_HANDLE`, просто оставьте значение пустым в `settings.py`.
- Все логи пишутся в `logs/soft_twitter.log`. Если что-то пошло не так — смотрите туда.

---

## ❓ Частые вопросы

- **Где хранить ключи?** — В `.env` (не коммитим) или в `settings.py`.
- **Можно ли поменять модель?** — Да, переменная `OPENAI_MODEL` в `settings.py` или `OPENAI_MODEL` в окружении.
- **Что если файл с постами пустой?** — Скрипт остановится с понятной ошибкой, заполните файл или укажите другой путь.
